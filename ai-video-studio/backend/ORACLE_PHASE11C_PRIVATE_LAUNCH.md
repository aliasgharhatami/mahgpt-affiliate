# MAH GPT Studio / Phase 11C — private Oracle preview launch checklist
Status: **staging only**. Do not advertise public video generation or enable production rendering until a full synthetic and uploaded-media test passes.

## Scope of this first bounded pilot
- Founder-only (the existing `studio_media_testers` allowlist); maximum 3 queue submissions per 24 hours per tester, one active job per account.
- Render preset `brief-preview-v1`: 8-second 720×1280 H.264/AAC MP4; text from frozen brief; first verified image/video optional; generated by the full Studio Docker image's FFmpeg adapter on Oracle ARM64. No AI-video generation or audio narration is implied.
- Supabase private queue with owner-only SELECT/INSERT, no browser UPDATE or worker RPC; worker endpoints require a strong server-only shared token.
- Cloudflare Pages R2 binding streams private input to Oracle and receives verified output. No R2 credentials or privileged Supabase key on Oracle, and no public inbound Oracle render port.
- Project becomes `completed` only after the gateway checks R2 output size/signature and the transactional finish RPC succeeds; it then receives the existing seven-day expiry marker.
- Existing seven-day R2 *physical deletion* is not enabled yet: that separate deletion gate MUST be completed before launching to all users.

## Database
Migration `ai-video-studio/backend/supabase/008_oracle_founder_render_queue.sql` is already applied to Supabase project `mah-gpt-studio`.
It creates `studio_render_jobs` and four service-role RPCs: `studio_worker_claim`, `studio_worker_renew`, `studio_worker_fail`, `studio_worker_finish`.
Validate that the browser can only read its own job rows and submit with the allowed preset.

## Cloudflare Pages secret configuration (NOT browser configuration)
Cloudflare dashboard → website Pages project → Settings → Variables and Secrets (Production):
- `STUDIO_ORACLE_PILOT_ENABLED` = `true` only when tested route code is deployed.
- `STUDIO_ORACLE_WORKER_TOKEN` = 64-character cryptographically random hex token, same as Oracle private env file; secret.
- `STUDIO_SUPABASE_SERVICE_ROLE_JWT` = *legacy* Supabase service_role JWT, a server-side secret from Supabase dashboard; never the publishable key.
- `STUDIO_MEDIA` R2 bucket binding must remain the existing private binding.
The Pages deployment must expose `/api/studio/worker/claim`, `/input`, `/output` over HTTPS, all rejecting callers without the worker token.
Never put either secret in `studio-config.js`, source code, or the browser.

## Oracle ARM64 staging commands
The following assumes the dedicated GitHub deploy key already works and the server is Ubuntu `ubuntu`:
```bash
cd ~/mahgpt-studio
git config core.sshCommand "ssh -i /home/ubuntu/.ssh/mahgpt_studio_github -o IdentitiesOnly=yes"
git fetch origin studio-oracle-phase11c-worker-20261105
git switch --track origin/studio-oracle-phase11c-worker-20261105
sudo docker build -f Dockerfile.cloud -t mahgpt-studio:arm64-preview .
```
Generate a private token **locally on Oracle**; paste it only into the Cloudflare Pages secret, never into a chat:
```bash
umask 077
mkdir -p ~/.config/mahgpt-studio
TOKEN="$(openssl rand -hex 32)"
printf 'STUDIO_ORACLE_RENDER_ENABLED=true\nSTUDIO_ORACLE_GATEWAY_URL=https://mahgpt.com\nSTUDIO_ORACLE_WORKER_TOKEN=%s\n' "$TOKEN" > ~/.config/mahgpt-studio/worker.env
chmod 600 ~/.config/mahgpt-studio/worker.env
printf 'Copy into Cloudflare STUDIO_ORACLE_WORKER_TOKEN:\n%s\n' "$TOKEN"
unset TOKEN
```
The worker cannot start until Pages has the same token and server-side Supabase legacy service JWT, the release flag is enabled, and the route code has been deployed.

Start **one** outbound-only worker after credentials and route are validated:
```bash
sudo docker run -d --name mahgpt-oracle-worker \
 --restart unless-stopped --cpus=1.7 --memory=8g --pids-limit=128 \
 --security-opt=no-new-privileges --cap-drop=ALL --read-only \
 --tmpfs /tmp:rw,nosuid,nodev,size=512m \
 --env-file /home/ubuntu/.config/mahgpt-studio/worker.env \
 mahgpt-studio:arm64-preview node scripts/cloud/oracle-queue-worker.mjs
sudo docker logs --tail 40 mahgpt-oracle-worker
```
No `-p` port mapping: outbound HTTPS polling only. Keep existing `mahgpt-studio-test` health container untouched.

## Private end-to-end acceptance test
1. Deploy source branches only after CI, verify server-side secrets and authentication. Do not enable public registration to submit renders.
2. Make one *synthetic*, rights-cleared test request in the owner's existing site account. Upload one small image or use text-only. Make sure the frontend private-preview flag is enabled only for tested deployment.
3. Confirm `queued → rendering → completed` in owner-visible status; check Oracle logs; ensure an MP4 in *private* R2 at `owner/project/r2/render/job/final.mp4`.
4. From My Projects → Media archive, download the MP4 and independently verify audio/video streams, 720×1280, ~8 seconds, and duration stability.
5. Confirm cross-user access to job, input and output fails, double submit is blocked, failed job resets project safely, and quota is enforced.
6. Confirm no credentials leak, no public 10000 port, Oracle resource usage within Always Free, and **physical 7-day retention** is tested and subsequently enabled.
7. Only then enable automatic GitHub-to-Oracle *verified* revisions and consider expanding beyond founder-only pilot.

## Rollback
Set `STUDIO_ORACLE_PILOT_ENABLED=false` on Pages and `STUDIO_ORACLE_RENDER_ENABLED=false` on Oracle env file; stop the worker:
```bash
sudo docker stop mahgpt-oracle-worker
```
Do not disable the entire website or unrelated affiliate automation.
