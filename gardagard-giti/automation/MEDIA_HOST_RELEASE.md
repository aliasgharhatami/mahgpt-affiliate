# گرد گیتی — انتقال کنترل‌شدهٔ رسانه به Render

## وضعیت در ۲۶ اکتبر ۲۰۲۶

میزبان جداگانه ایجاد و به HTTPS وصل شده است: https://gerde-giti-media.onrender.com

- شاخهٔ میزبان: `giti-media-host-20261026`
- هر عکس یا ویدیو در `public/media/YYYY-MM-DD/<story-id>/` قرار می‌گیرد
- انتشار اینستاگرام **خاموش** است
- تنها رسانه‌هایی قابل انتقال‌اند که به‌صورت مستقل از نظر حقیقت خبر، منبع، مجوز تصویر، کیفیت نریشن و متن فارسی بررسی شده باشند

### هرگز پیش‌نمایش را به عنوان خبر منتشر نکن

فایل‌های قبلی `render_daily.py` دارای واترمارک «پیش‌نمایش — منتشر نشود» و وضعیت `preview_not_approved` هستند. انتقال‌دهنده عمداً آن‌ها را رد می‌کند.

برای انتقال نسخهٔ نهایی، ابتدا باید:
۱. صف مستقل روز با `status: approved` و سه پرچم بررسی واقعیات، مجوز رسانه و فارسی در GitHub ثبت شود؛ `queue.live` همچنان `false` بماند.
۲. یک بستهٔ نهایی بدون واترمارک، با `review.json` مربوط به همان خبر، منبع دقیق و تأییدهای بازبینی وجود داشته باشد.
۳. تاریخ، شناسه، مدت ۳۰–۱۸۰ ثانیه، صوت واقعی و تصاویر مجاز با اطلاعات صاحب اثر در بسته یکسان باشند.
۴. پس از آن گردش‌کار `giti-promote-reviewed-media.yml` با شناسه اجرای تولید رسانه و عبارت `APPROVED MEDIA ONLY` اجرا می‌شود.
۵. گردش‌کار پیش از ساخت URL عمومی، JPEG/MP4 را از نظر قالب، کیفیت، مدت، مسیر امن و تأییدهای رسانه بررسی می‌کند؛ سپس SHA-256 فایل بیرونی را با فایل روی GitHub تطبیق می‌دهد.

این روند **هیچ پستی در اینستاگرام منتشر نمی‌کند**؛ تنها URLهای HTTPS واقعی برای گام انتشار ایجاد می‌کند.

## مشکل کشف‌شدهٔ استقرار خودکار

در آزمایش اولیه، آپلود فایل‌های تست به شاخه میزبان انجام شد، اما Render با وجود `autoDeploy=yes` استقرار خودکار تازه آغاز نکرد. یک استقرار با API Render انجام شد تا انتقال فایل آزمایش شود. اگر این مسئله پابرجا بماند، برای اجرای بی‌حضور باید اتصال GitHub به Render یا Deploy Hook مستقل آن اصلاح شود. راهکار مطمئن معمولاً یک `GITI_RENDER_DEPLOY_HOOK` در GitHub Actions Secrets است؛ این مقدار **نباید وارد فایل یا چت شود**. تا آن زمان نمی‌توان وعده آپلود خودکارِ بی‌نیاز از دخالت داد.

## کنترل هزینه و پایداری

همه کارها در سهمیه رایگان GitHub Actions، Gemini AI Studio و Render Static Site انجام می‌شوند؛ مصرف رندر و پهنای‌باند باید پایش شود. به‌خاطر اندازه MP4، استفاده دائمی از تاریخچه Git برای همه ویدیوهای روزانه ممکن است پایدار نباشد. در صورت بالا رفتن حجم مخزن، باید مسیر میزبانی فایل را به شیوهٔ مناسب برای محتوای رسانه‌ای تغییر داد.
